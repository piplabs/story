# DCAP On-Chain Remote Attestation — Devnet Deployment Guide

> Tested and verified on 2026-03-18. DKG Round 1 completed successfully with real
> Automata DCAP on-chain SGX quote verification (gas_used ≈ 7.7M per registration).

## Overview

This guide covers deploying the full Automata DCAP attestation stack on the Story devnet
to replace the MockValidationHook with real on-chain SGX remote attestation verification.

## Why V3 QuoteVerifier?

Automata DCAP provides three QuoteVerifier versions:

| Version | SGX | TDX | TCB Info | Description |
|---------|-----|-----|----------|-------------|
| **V3** | O | X | V2 (SGX only) | SGX-only quote format |
| **V4** | O | O | V3 (SGX+TDX) | SGX + TDX dual support |
| **V5** | O | O | V3 + TD1.5 | SGX + TDX with TD 1.5 report |

All three support SGX attestation. However, the quote **version** is determined by the
TEE runtime (Gramine) that generates it, not by us. Gramine SGX currently produces
**V3 quotes** (header.version == 3). The `AutomataDcapAttestationFee` entrypoint
reads the quote header version and automatically routes to the matching QuoteVerifier.

Since only V3 quotes are generated by our Gramine-based story-kernel, we only **need**
`V3QuoteVerifier`. V4/V5 can optionally be deployed for future-proofing (e.g., if the
TEE runtime is upgraded to emit V4/V5 quotes, or if TDX enclaves are introduced).

To deploy V4/V5 alongside V3, add the following to `DeployAllDevnet.s.sol`:

```solidity
V4QuoteVerifier v4 = new V4QuoteVerifier(p256Verifier, address(router));
attestation.setQuoteVerifier(address(v4));
router.setAuthorized(address(v4), true);

V5QuoteVerifier v5 = new V5QuoteVerifier(p256Verifier, address(router));
attestation.setQuoteVerifier(address(v5));
router.setAuthorized(address(v5), true);
```

The entrypoint registers each verifier by its `quoteVersion()` return value, so
multiple verifiers coexist without conflict.

**Verification pipeline:**
```
DKG.register() → SGXValidationHook.validateReport()
  → AutomataDcapAttestationFee.verifyAndAttestOnChain(rawQuote, tcbEvalNumber=18)
    → V3QuoteVerifier.verifyQuote()
      → QE Identity verification (via EnclaveIdentityDao)
      → X.509 cert chain verification (via PcsDao)
      → CRL check
      → P256 ECDSA signature verification (via software P256Verifier)
      → TCB level matching (via FmspcTcbDao)
  → MRENCLAVE check (offset 112 in raw quote)
  → Data commitment check (offset 368 in raw quote)
```

## Key Findings & Bugs Fixed

### 1. P256 precompile not available
- Story-geth devnet (chain 1511) does not support RIP-7212 P256 precompile at `0x100`
- **Fix**: Deploy daimo-eth P256 software verifier (included in DeployAllDevnet.s.sol)

### 2. Block gas limit
- TCB Info upload requires ~22M gas; default block gas limit starts too low
- **Fix**: Set `gasLimit` in `genesis-geth.json` to integer `30000000` (NOT hex string `"0x1C9C380"`).
  story-geth's `math.HexOrDecimal64` JSON parser does not parse hex strings correctly in this field.
  Must be a JSON integer: `"gasLimit": 30000000`

### 3. Genesis whitelistEnclaveType not persisted
- `GenerateAlloc.s.sol` calls `whitelistEnclaveType` via `vm.prank`, but this state change is
  not reliably persisted into the alloc dump.
- **Fix**: Call `whitelistEnclaveType` explicitly after chain start (in the DCAP setup step),
  using `cast send` with the `TEST_DKG_OWNER` private key.

### 3. Geth FilterLogCacheSize crash
- Story-geth crashes in `filtermaps/map_renderer.go` during large contract deployments
- **Fix**: Set `FilterLogCacheSize = 0` in `~/.story/geth/config/geth.toml`

## Step-by-Step Deployment

### Step 1: Prepare Genesis

```bash
cd story/contracts

# Edit SGX_CODE_COMMITMENT in GenerateAlloc.s.sol to match kernel MRENCLAVE
# Generate alloc
forge script script/GenerateAlloc.s.sol --tc GenerateAlloc -vvv --chain-id 1511

# Update EL genesis alloc + set gasLimit to 30M (MUST be integer, not hex string)
python3 -c "
import json
with open('genesis-geth.json') as f: g = json.load(f)
with open('contracts/local-alloc.json') as f: a = json.load(f)
g['alloc'] = a
g['gasLimit'] = 30000000  # integer, NOT '0x1C9C380'
with open('genesis-geth.json', 'w') as f: json.dump(g, f, indent=2)
"

# Compute execution block hash
geth --state.scheme=hash --datadir /tmp/h init genesis-geth.json
HASH=$(geth --datadir /tmp/h --exec "eth.getBlock(0).hash" console 2>/dev/null | tr -d '"')
EXEC_B64=$(echo -n "${HASH#0x}" | xxd -r -p | base64)

# Update CL genesis
# Set chain_id = "<cl-chain-id>"
# Set app_state.evmengine.params.execution_block_hash = $EXEC_B64
```

### Step 2: Start Chain (follow DEVNET_RUNBOOK.md Part 1)

Key reminders:
- Set `FilterLogCacheSize = 0` in geth.toml on all machines

### Step 3: Deploy DCAP Contracts (on val1)

```bash
cd ~/automata-dcap-attestation/evm

OWNER=<owner-addr> \
TCB_EVAL_NUMBER=18 \
forge script forge-script/DeployAllDevnet.s.sol:DeployAllDevnet \
    --rpc-url http://localhost:8545 \
    --private-key $DKG_OWNER_KEY \
    --broadcast --legacy --gas-price 20000000000 --slow -vv
```

This deploys 15 contracts including P256 software verifier.

`TCB_EVAL_NUMBER=18` because Intel's current QE Identity and TCB Info collateral
both carry `tcbEvaluationDataNumber: 18`. The versioned DAOs (EnclaveIdentityDao,
FmspcTcbDao) are deployed with this number and will only accept collateral whose
`tcbEvaluationDataNumber` matches. To find the current value, check the Intel PCS
API response: `curl -s https://api.trustedservices.intel.com/sgx/certification/v4/qe/identity | jq '.enclaveIdentity.tcbEvaluationDataNumber'`.

### Step 4: Configure SGXValidationHook

```bash
# SGX_HOOK is the SGXValidationHook proxy address from the genesis alloc generation output
# (logged as "SGXValidationHook proxy deployed at:" when running GenerateAlloc.s.sol)
SGX_HOOK=<sgx-hook-proxy-addr>
# DCAP_ATTESTATION is the AutomataDcapAttestationFee address from Step 3 deploy output
DCAP_ATTESTATION=<attestation-addr>

# Set automata validation address
cast send $SGX_HOOK "setAutomataValidationAddr(address)" $DCAP_ATTESTATION \
    --rpc-url http://localhost:8545 --private-key $KEY --gas-price 20000000000 --legacy

# Set TCB evaluation data number (must match Intel's current value)
cast send $SGX_HOOK "setTcbEvaluationDataNumber(uint32)" 18 \
    --rpc-url http://localhost:8545 --private-key $KEY --gas-price 20000000000 --legacy
```

### Step 5: Whitelist Enclave Type

**Required**: The genesis `vm.prank` whitelisting is not persisted into the alloc, so this
must be called explicitly after chain start.

```bash
ENCLAVE_TYPE=$(cast --to-bytes32 1)
cast send 0xCcCcCC0000000000000000000000000000000004 \
    "whitelistEnclaveType(bytes32,(bytes32,address),bool)" \
    $ENCLAVE_TYPE \
    "(0x<MRENCLAVE>,$SGX_HOOK)" \
    true \
    --rpc-url http://localhost:8545 --private-key $KEY --gas-price 20000000000 --legacy

# Verify
cast call 0xCcCcCC0000000000000000000000000000000004 \
    "isEnclaveTypeWhitelisted(bytes32)(bool)" $ENCLAVE_TYPE --rpc-url http://localhost:8545
# Must return: true
```

### Step 6: Upload Intel Collateral

#### 6a. PCS Certificates & CRLs

Upload in this exact order (Root CA first, then others):

```bash
# PCS_DAO is the AutomataPcsDao address from Step 3 deploy output
PCS_DAO=<pcs-dao-addr>

# Fetch from Intel
curl -sD h.txt "https://api.trustedservices.intel.com/sgx/certification/v4/pckcrl?ca=platform&encoding=der" -o pck_crl.der
curl -s "https://certificates.trustedservices.intel.com/IntelSGXRootCA.crl" -o root_crl.pem
openssl crl -in root_crl.pem -inform PEM -outform DER -out root_crl.der
# Extract certs from issuer chain header...

# Upload (order matters!)
cast send $PCS_DAO "upsertPcsCertificates(uint8,bytes)" 0 $ROOT_CA_DER_HEX ...   # Root CA
cast send $PCS_DAO "upsertPcsCertificates(uint8,bytes)" 2 $PLATFORM_CA_HEX ...   # Platform CA
cast send $PCS_DAO "upsertPcsCertificates(uint8,bytes)" 3 $SIGNING_CA_HEX ...    # Signing CA
cast send $PCS_DAO "upsertRootCACrl(bytes)" $ROOT_CRL_HEX ...                     # Root CRL
cast send $PCS_DAO "upsertPckCrl(uint8,bytes)" 2 $PCK_CRL_HEX ...                # PCK CRL
```

#### 6b. Grant ATTESTER_ROLE on Versioned DAOs

```bash
# Solady OwnableRoles: ATTESTER_ROLE = _ROLE_0 = 1
cast send $ENCLAVE_ID_DAO "grantRoles(address,uint256)" $OWNER 1 ...
cast send $FMSPC_TCB_DAO "grantRoles(address,uint256)" $OWNER 1 ...
```

#### 6c. QE Identity

Use the `UploadQEOnly.s.sol` forge script (ABI struct encoding required).

#### 6d. TCB Info (requires block gas limit ≥ 22M)

**Important**: Block gas limit starts at ~9M and must be increased to ≥22M before uploading TCB Info.

```bash
# Send dummy txs to increase gas limit
for i in $(seq 1 300); do
    cast send 0x01 --value 0 --gas-limit 10000000 ...
done
# Wait until gasLimit > 22M, then:
```

Use the `UploadTCBOnly.s.sol` forge script with `--gas-limit 22000000`.

### Step 7: Start Kernels & Wait for DKG

Follow DEVNET_RUNBOOK.md Steps 8-9. The kernel config must use:
- `chain_id = "story-1001511"`
- Internal IPs for witness_addrs (Azure VMs may not route via public IPs)

## Troubleshooting

| Issue | Cause | Fix |
|-------|-------|-----|
| `exceeds block gas limit` for TCB Info | Block gas limit too low | Send dummy txs to increase to ≥22M |
| `Code commitment does not match` | MRENCLAVE offset bug or wrong SGX_CODE_COMMITMENT | Ensure offset 112 in SGXValidationHook, verify MRENCLAVE matches |
| `Data commitment does not match` | DKG.sol uses abi.encode instead of abi.encodePacked | Use commit `113ef1a1` or later |
| `Unauthorized()` on upsertEnclaveIdentity | Missing ATTESTER_ROLE | Grant role: `grantRoles(address,uint256)` with role=1 |
| Geth crash in filtermaps | FilterLogCacheSize default causes OOM | Set `FilterLogCacheSize = 0` in geth.toml |
| `unknown chain ID` panic | CL genesis chain_id doesn't match UpgradeHistories | Use `story-1001511` with `network=local` |
| P256 verification fails silently | RIP-7212 precompile not available | Deploy P256 software verifier (included in DeployAllDevnet.s.sol) |
